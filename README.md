# Lobby

The public front of a private house. The landing page shows the house on the lake: the **Market Board
Facade** is entered by the main gate and is open to everyone; the other rooms are reached through the
windows of the quarter they belong to, and each asks for a key.

Every scene has a **photo slot**: a photorealistic image with the right name in `assets/img/` is
used automatically; until then a drawn SVG scene stands in. The images are generated with the OpenAI
image API by the *Generate scene images* workflow (`tools/gen_images.py`, prompts in
`assets/img/prompts.json`), which needs the repository secret `OPENAI_API_KEY`. The Fin Lab analyst
is a photograph (`fin-lab/assets/analyst.jpg`) with generated keyframes of the same woman that the
page crossfades between so she blinks, turns to you, talks, waves and points.

**Live site:** https://hongguqaz.github.io/Lobby/ (after GitHub Pages is enabled, see below)

```
Google Drive / laptop / phone  --Drive's drives-sync/, sync/-->  Drive (private)     add-only; see Drive's sync/README.md

Drive (private)                              Lobby (public, this repository)
  market-board-facade/  data + pipeline  -->   market-board-facade/  the board, as a dashboard   (open)
  fin-lab/              reserved         -->   fin-lab/              trading-floor office        (key)
  legal-quarter/        reserved         -->   legal-quarter/        walnut-panelled chambers    (key)
  library/              reserved         -->   library/              the study in the west tower (key)
  maiden-hall/          reserved         -->   maiden-hall/          drawing room over the gate  (key)
  garden/               reserved         -->   garden/               the grounds                 (key)
  bedroom/              reserved         -->   bedroom/              the east tower              (key)
                                               index.html            the painting
```

Only result files cross from Drive to Lobby. Source data never enters this repository. Raw material
reaches Drive from Google Drive and from device folders through the Drives Sync app and Drive's `sync/`
tool, both of which live in the private Drive repository and only ever add files (see Drive's `sync/README.md`).
Nothing in this repository talks to Drive: the site is static, and the only credential between the two
repositories is held by Drive and can write here, never the other way round.

## The rooms and where they sit

| Room | Where in the house | Why there | Status |
|---|---|---|---|
| Market Board Facade | the main gate | meant to be seen from outside | open, sample data |
| Fin Lab | west wing, ground floor | what it gathers feeds the board outside | FixC report and Daily Picks boards live, rest reserved |
| Legal Quarter | east wing, ground floor | the law of the market beside the market | reserved |
| Maiden Hall | piano nobile, over the gate | where the work of both wings is written up | reserved |
| Library | west tower | the wider reading the lab draws on | reserved |
| Bedroom | east tower | private quarters, furthest from the gate | design only |
| Garden | the grounds | outside the walls, for lighter things | design only |

`assets/rooms.js` is the registry the landing page and the gate read from; each room carries a
`hotspot` box on a 1600 x 900 grid that `assets/castle.js` draws as a clickable overlay over the
painting or the photo. Move the boxes if your `castle.jpg` is composed differently.

## Keys

Every room except the facade is behind a key. The gate is client-side (`assets/gate.js`): each room's
key is stored as a SHA-256 hash, the visitor's key is hashed in the browser and compared, and an
unlocked room is remembered for the browser session. **All rooms currently use the key `1111`.**

To change a key, hash the new one and paste it into `KEYS` in `assets/gate.js`:

```bash
python3 -c "import hashlib;print(hashlib.sha256(b'NEW-KEY').hexdigest())"
```

Because the site is static and public, this keeps casual visitors out but is **not real security**:
the room pages are in the repository and anyone who reads the page source can bypass the gate. For
material that must stay private, keep it in Drive.

## The Market Board Facade

`market-board-facade/index.html` renders `market-board-facade/data/dashboard.json`. The board is meant
for financial market data (uploaded, auto-updated, or extracted from the Fin Lab); until that database
exists it demonstrates the mechanics with a synthetic vendor dataset, and says so in a banner. The
published data holds names and per-period sums and counts only, never rows, identifiers or free text.

## The Fin Lab boards: FixC report and FixC Daily Picks

Two boards under the Fin Lab room show what the **FixC** Claude Project writes into the private Drive
repository, `fin-lab/FixC report/` (weekly/, daily/, notes/; a PDF and its same-name .md; the day's
`daily/YYMMDD_FixC_Daily_Picks.md`). Nothing is copied here: both pages list that folder and fetch each
file through the GitHub API, so a report is on the board as soon as FixC pushes it.

- **A plain board.** `fin-lab/reports/` (FixC report) lists every report as a row, its file name the
  title, newest first, twenty to a page with page numbers below; the kind (일간·주간·노트) comes from
  the sub-folder. `fin-lab/picks/` (FixC Daily Picks) lists the `*_Picks.md` files the same way. A row's
  address on the wrong board forwards to the right one.
- **A post.** Under the title, a strip lists everything the post opens: FixC's own files first (the PDF,
  its .md twin), then the day's Daily Picks file, then the documents that file names, the originals
  in `fin-lab/Fin Docraw/` (and their renderings when the desk knows one); a picks post adds the day's
  report files after its picks. The viewer below opens FixC's PDF by default (its .md when there is no
  PDF; a picks post opens its own .md), and any item in the strip with one click; each item also
  downloads or opens on GitHub. `#post=<id>` deep-links a post, `#post=<id>&file=<path>` a post with
  one of its items open, `#page=<n>` a page of the list.
- **PDFs** are drawn page by page with pdf.js (`fin-lab/reports/vendor/pdfjs/`, Apache-2.0), so they
  open in place on every browser, phones included; the browser's own viewer is the fallback.
  Markdown renders in the page (own small renderer, output escaped, numbered lists keep their numbers),
  HTML in a sandboxed frame with its figures inlined, images inline, other formats download only.
- **Token**: both pages need a GitHub token with *Contents: Read* on Drive, entered once under ⚙ and
  kept in this browser's localStorage only (key `ds.github.token`); they share the setting.
- **Index and fallback**: the Fin Desk in Drive writes `fin-lab/FixC report/.fin-desk/board.json` on every
  push (registered days, picks resolved to paths and renderings). Until it has run for a new file, the
  pages date the post from its name and read the picks from the Daily Picks text themselves, looking
  the originals up in `Fin Docraw/`.
- **Gate**: the boards sit behind the Fin Lab key like the room itself; the key is a courtesy, the token
  is what actually protects the reports.
- **Tests**: `node fin-lab/reports/test-board.mjs` covers file-name parsing, grouping, a post's items,
  the Daily Picks text, the Markdown renderer and repository-path resolution; the Pages workflow runs it.

## Viewing locally

Open `index.html` in a browser, or serve the folder:

```bash
python -m http.server 8000     # then open http://localhost:8000/
```

## One-time setup

- **GitHub Pages**: Settings > Pages > *Build and deployment* > Source: **GitHub Actions**. Until it is
  enabled the deploy job is skipped with a warning and only the data check runs.
- **Publishing token**: Drive needs a secret `LOBBY_DEPLOY_TOKEN` with *Contents: Read and write* on
  this repository. Details are in Drive's README.
- **Keys**: change the shared `1111` before putting anything sensitive behind a door.
- **Scene images**: add the repository secret `OPENAI_API_KEY`, then run the *Generate scene
  images* workflow from the Actions tab. It commits the images and redeploys the site.
